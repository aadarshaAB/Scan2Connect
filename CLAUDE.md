## Project Overview

**Scan2Connect** is a Windows GUI app (PySide6) that scans a WiFi QR code from the webcam and connects the PC to that network. It is being upgraded from a single-file prototype into a packaged, installable Win11 app followi ng `enhancement_plan.md`.

Reference docs:
- `enhancement_plan.md` — the ordered work queue (tasks `E-01` … `E-28`). **Work one task at a time, in order.**
- `CODEBASE_GUIDE.md` — deep dive into the original code (pre-plan snapshot).
- The **Session Log** at the bottom of this file — what is done, in progress, and next.

## Start-of-session routine

1. Read the Session Log below to find the current task and any notes left last time.
2. `git log --oneline -5` and `git status` to confirm the log matches reality.
3. Open the task's entry in `enhancement_plan.md` and work only on that task.

## Workflow: one task = one commit

1. Pick the next `todo` task from the Session Log (respect the order in `enhancement_plan.md`).
2. Mark it `in-progress` in the Session Log.
3. Implement only what the task describes. If something unrelated needs fixing, note it in the log's "Notes" column or add a backlog item — don't fold it into this commit.
4. Verify: `ruff check .`, `pytest` (once tests exist), and run the app for anything UI-facing.
5. Update the Session Log row to `done` with the short commit hash, and update any section of this file the task made stale (commands, architecture, dependencies).
6. Commit the code **and** this file together, using the commit message from the task entry.
7. Don't start the next task in the same commit.
8. I have created a own cutom / commit command so dont commit just remind me to commit from now one.
9. Commit message should be short precise and direct.

## Commit message convention (Conventional Commits)

```
<type>(<scope>): <summary>

<optional body — what and why, not how>

Refs: E-05
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

**Types**
| Type | Use for |
|---|---|
| `feat` | new user-visible capability or enhancement |
| `fix` | bug fix |
| `perf` | performance improvement with no behaviour change |
| `refactor` | code restructuring with no behaviour change |
| `build` | packaging, dependencies, PyInstaller/Inno, `pyproject.toml` |
| `ci` | GitHub Actions |
| `test` | adding or fixing tests only |
| `docs` | README, CLAUDE.md, plan docs only |
| `chore` | repo housekeeping (`.gitignore`, tooling config) |
| `style` | formatting only |

**Scopes** (optional, lowercase): `qr`, `wifi`, `camera`, `ui`, `deps`, `packaging`. Omit when the change is repo-wide.

**Rules**
- Summary: imperative mood, lowercase, no trailing period, ≤ 72 chars (`add`, not `added`/`adds`).
- Breaking change: add `!` after the scope (`feat(wifi)!: ...`) and a `BREAKING CHANGE:` footer.
- Always include `Refs: E-NN` for plan tasks (or `B-NN` for backlog). Use `Fixes #123` for GitHub issues.
- One task per commit; never mix a `feat` with an unrelated `fix`.
- Session-Log-only updates use `docs: update session log`.
- Don't auto run script to test. Tell me manually perform test after each phase / feature is completed.

Examples:
```
chore: add .gitignore and stop tracking build artifacts
feat(qr): parse full WIFI: payload with security type, hidden flag and escapes
fix(ui): pause scanning while dialogs are open and debounce repeat QR codes
```

## Current architecture (update as tasks land)

Split into the `scan2connect` package (E-03), 1:1 moves from the original `main.py`, no behaviour change:
- `scan2connect/__main__.py` — `QApplication` with `setOrganizationName`/`setApplicationName("Scan2Connect")` (added E-10, required for `QSettings()` to persist reliably), applies `ui/theme.py` stylesheet, creates/shows `WifiQRScanner`.
- `resources.py` — `resource_path(rel)`: resolves against `sys._MEIPASS` when frozen (PyInstaller), else the package directory. Used for `assets/app_icon.ico`.
- `logging_setup.py` (E-15) — `configure_logging()` attaches a `RotatingFileHandler` (1MB × 3 backups) to the root logger, writing to `log_dir()` = `%LOCALAPPDATA%\Scan2Connect\logs\scan2connect.log`; called once from `__main__.py::main()` before the `QApplication` is created. Standard `logging.getLogger(__name__)` used throughout — no custom logger classes.
- `ui/main_window.py` — `WifiQRScanner(QMainWindow)` — camera preview and QR detection run off the GUI thread on `camera/worker.py::CameraWorker` (E-20): `start_camera()` creates and starts it, connecting `frame_ready(QImage)` → `display_frame()` (paints only — no capture/decode work on the GUI thread) and `qr_found(str, corners)` → `on_qr_found()` (same `WIFI:` prefix check + `parse_wifi_qr()` + `handle_wifi_qr_found()` flow as before), `camera_error(str)` → `on_camera_error()` (shows the same `QMessageBox.critical` `start_camera()` used to show inline, since `open_camera()` now runs inside the worker thread). `stop_camera()` disconnects the signals and calls `camera_worker.stop()`, which flips a mutex-guarded flag and blocks (`QThread.wait()`) until the worker's `run()` loop exits and releases the capture. Orchestrates the connect flow. Scanning pause + debounce (E-21): since the camera worker keeps running and emitting `qr_found` on its own thread even while a modal confirm/progress/result dialog is up, `on_qr_found()` checks a `_dialog_open` flag first and drops the signal if any dialog is currently open — `_dialog_open` is set `True` right before `show_wifi_details_dialog()`'s blocking `exec_()` in `handle_wifi_qr_found()` and only cleared once the whole flow finishes: immediately on Cancel/No, or (if Yes) not until `connect_to_wifi()`'s progress dialog resolves and `handle_connection_result()`'s own result `QMessageBox` closes — every early-return branch inside `connect_to_wifi()` (WLAN query error, no adapter, adapter picker cancelled) also clears it so a rejected/failed attempt doesn't leave scanning permanently paused. Separately, `handle_wifi_qr_found()` takes an optional `payload` (the raw `WIFI:...` string, passed by `on_qr_found()` but not by `scan_image_file()`, which has no live stream to debounce) — on Cancel/No it's remembered in `_ignored_payload` with `_ignored_until = now + DEBOUNCE_SECONDS` (10s), and `on_qr_found()` skips re-opening the dialog for that exact payload until the debounce window passes, so a QR code still in the camera's view after a Cancel doesn't immediately reopen the same dialog. `start_camera()` (E-12) calls `open_camera()` and shows its `error_message` in a `QMessageBox` on failure instead of opening `cv2.VideoCapture` directly. `connect_to_wifi()` enumerates adapters via `wlanapi.list_interfaces()` first: 0 → error dialog ("No WiFi adapter found or WiFi is off"), 1 → auto-selected, >1 → `resolve_adapter()` shows a `QInputDialog.getItem` picker and remembers the chosen GUID in `QSettings` (key `wifi/adapter_guid`), reused on future connects while still present. Image-file scanning (E-14): the "Open image…" button (`open_image_dialog()`) runs `QFileDialog.getOpenFileName`, and the window itself accepts drag-and-drop of an image file (`setAcceptDrops(True)`, `dragEnterEvent`/`dropEvent`); both funnel into `scan_image_file(path)`, which runs `camera/worker.py::detect_qr_codes_in_image()` on the file and shows a "No WiFi QR Code Found" warning if nothing decodes. The webcam path (`update_frame`) and the image path now share `handle_wifi_qr_found(creds)` for the confirm-and-connect step, instead of duplicating the confirm-dialog/connect call; it also logs the found SSID/security/hidden flag (E-15). A `&Help` menu (`setup_menu()`, E-15) has "Open log folder", which opens `logging_setup.log_dir()` via `QDesktopServices.openUrl`.
- `ui/dialogs.py` — `CustomMessageBox(QMessageBox)` — SSID/password confirmation with Yes / No / Copy Password.
- `ui/theme.py` — `STYLESHEET` string applied to the `QApplication`.
- `qr/parser.py` — `parse_wifi_qr(data)` regex parser (module-level function, not a method).
- `camera/worker.py` — `detect_qr_codes(frame)`: `cv2.QRCodeDetectorAruco().detectAndDecodeMulti(frame)` wrapper, returns `list[(payload, corners)]`. `open_camera(index=0)` (E-12): opens with `cv2.CAP_DSHOW` and returns `(capture, error_message)` — classifies failures into 3 actionable messages instead of one generic "Cannot access camera": privacy-blocked (checked first, before even trying to open, via `is_camera_privacy_blocked()` reading the `CapabilityAccessManager\ConsentStore\webcam` registry key under both `HKCU` and `HKLM` — either set to `Deny` blocks access), no device present (`is_camera_present()` probes the index independently once the main open attempt fails), or in-use-by-another-app (device present but open still failed). Opens in ~0.5s on this machine, including the registry check. Each outcome is logged (E-15): `INFO` on success, `WARNING` per failure reason. `detect_qr_codes_in_image(path)` (E-14): `cv2.imread(path)` then the same `detect_qr_codes()`; returns `[]` for an unreadable/missing file or a decoded image with no QR code, letting the UI treat both the same way ("No WiFi QR Code Found"). `CameraWorker(QThread)` (E-20): owns capture + detection off the GUI thread — `run()` calls `open_camera()` internally (emitting `camera_error(str)` and returning if it fails), then loops `capture.read()`, converting every frame to a `QImage` and emitting `frame_ready(QImage)` so the GUI thread only paints, while `detect_qr_codes()` itself only runs every `DETECT_EVERY_N_FRAMES = 3`rd frame on a 0.5x-downscaled copy (corners scaled back up before emitting `qr_found(str, corners)`) since decode, not capture, was the expensive step causing stutter on the old 30ms-`QTimer`-on-GUI-thread design. `stop()` sets a mutex-guarded flag the loop polls once per frame and blocks on `QThread.wait()` until `run()` exits and releases the capture — avoids the thread being killed mid-`VideoCapture` call.
- `camera/devices.py` — `list_cameras()` (E-13): probes indices `0..9` with `cv2.CAP_DSHOW`, stopping after `MAX_CONSECUTIVE_MISSES = 2` indices in a row fail to open (keeps the common 1-2 camera case fast instead of always probing to 9); OpenCV's own DSHOW warning logging is silenced around the probe (`cv2.setLogLevel`, restored after) since failed-index warnings are expected noise, not errors. Pairs each working index with a human-readable name from `_device_names()` — OpenCV has no API for camera names, so this shells out to `Get-CimInstance Win32_PnPEntity` via PowerShell (no new dependency; matched to DSHOW probe order positionally, best-effort — falls back to `"Camera N"` per index if WMI yields fewer names or fails entirely). Not wired into the UI yet — that's E-25.
- `wifi/connector.py` — `WifiConnector(QThread)`, on the native WLAN API: builds a profile via `wifi/profile.py`, `WlanSetProfile`s it per-user (overwrites only the same-SSID profile, other saved profiles untouched), `WlanConnect`s, polls `current_connection` up to 15s per attempt, up to `MAX_ATTEMPTS = 3` attempts on plain timeout (E-11). Logs (E-15) the already-connected short-circuit, each attempt's outcome (`connected`/`cancelled`/`wrong_password`/`timeout`), and any raised exception. Signals unchanged: `status_updated(str)`, `connection_completed(bool, str)`. Constructor takes `(credentials, interface_guid=None)` — the full `WifiCredentials` object so security type and hidden-network flag reach the profile builder, plus an optional pre-resolved adapter GUID (E-10; falls back to auto-picking the first enumerated adapter when omitted, used by tests and any caller that hasn't resolved one). `ui/main_window.py` always passes the GUID it resolved. State machine (E-11): already-connected-to-target-SSID short-circuits before touching any profile ("Already connected to {ssid}"); a public `cancel()` sets a flag polled once per second-long poll iteration ("Cancelled", not wired to any UI button yet — that's later UI work); wrong-password is detected heuristically by polling `wlanapi.interface_state()` — if the interface reaches `WLAN_INTERFACE_STATE_AUTHENTICATING` and then falls back to `WLAN_INTERFACE_STATE_DISCONNECTED` without ever reaching the target SSID, that's reported as "Wrong password" immediately (no retry, since retrying won't fix a bad password); a plain timeout (never even reaches authenticating) retries up to `MAX_ATTEMPTS` times before reporting "Connection Timeout". Every failure path (wrong password, cancel, final timeout) calls `_cleanup()`: best-effort `wlanapi.disconnect()` + `delete_profile()` of the profile this run added, so no stale/failed profile is left behind. `pywifi`/`comtypes` fully removed.
- `wifi/wlanapi.py` — ctypes bindings for `wlanapi.dll` (WlanOpenHandle/CloseHandle, EnumInterfaces, QueryInterface, Get/Set/DeleteProfile, Connect, Disconnect, RegisterNotification, FreeMemory). `WlanHandle` context manager; `list_interfaces()` / `current_connection(guid)` helpers; `set_profile(..., all_user=False)` for per-user profiles; `interface_state(wlan_handle, interface_guid)` (E-11) re-enumerates and returns the `WLAN_INTERFACE_STATE_*` value for one interface, used by the connector's wrong-password heuristic. Every DLL call's Win32 return code is logged (E-15): `_check()` (used by most calls) logs success at `INFO` and failure at `WARNING` before raising `WlanApiError`; `WlanCloseHandle` (no `_check`, since a close failure shouldn't raise) and `WlanQueryInterface` (returns `None` on failure rather than raising, since "not connected" is a routine, frequently-polled outcome) log directly at their call sites.
- `wifi/profile.py` — `build_profile_xml(creds: WifiCredentials) -> str`: WLAN_profile v1 XML for WPA2PSK/AES, WPA3SAE/AES, WPA/TKIP, open/none, WEP; `<nonBroadcast>` for hidden networks; XML-escapes SSID/key. WPA3SAE validated as a plain v1-namespace profile — no v3 namespace or `transitionMode` element needed (confirmed against `netsh wlan add profile`, which is stricter than XML well-formedness).
- `packaging/scan2connect.spec` (E-16) — onedir PyInstaller spec (replaces the deleted root `wifi_qr_scanner.spec`, which was stale — it still referenced pre-E-03 `main.py`/`app_icon.ico` paths). Analysis entrypoint is `scan2connect/__main__.py`; `datas` bundles `scan2connect/assets/app_icon.ico`; excludes `QtWebEngine*`, `QtQuick*`/`QtQml`, `Qt3D*`, `QtMultimedia*`, `QtCharts`, `QtDataVisualization`, plus a post-`Analysis` filter dropping all `*.qm` Qt translation files; `upx=False` (per task); `EXE(..., exclude_binaries=True)` + `COLLECT(...)` for a real onedir layout (`dist/Scan2Connect/Scan2Connect.exe` + `_internal/`); icon and `version=packaging/version_info.txt` (a `VSVersionInfo` resource, version synced with `pyproject.toml`'s `0.1.0`) set on `EXE`. Build with `pyinstaller packaging/scan2connect.spec` from the repo root (the spec resolves paths via `Path(SPECPATH).parent` so it doesn't depend on CWD).
- `packaging/installer.iss` (E-17) — Inno Setup script that packages `dist/Scan2Connect/` (must be built first) into a single-file setup exe. `PrivilegesRequired=lowest` + `{autopf}`/`{autodesktop}` constants so it installs per-user with no admin prompt on a standard account; Start Menu shortcut always created, desktop shortcut via an unchecked-by-default `[Tasks]` entry, uninstaller auto-registered, `SetupIconFile`/`UninstallDisplayIcon` both point at `app_icon.ico`. `AppVersion` is an ISPP `#define` overridable via `iscc /DAppVersion=x.y.z` — deliberately **not** parsed out of `pyproject.toml` by the `.iss` script itself: ISPP has no TOML parser, and without Inno Setup installed on this dev machine to actually compile against, a hand-written string-scanning preprocessor loop couldn't be verified correct (same class of risk as E-08's initial wrong WPA3 XML guess) — user chose passing the version in via `/D` instead (falls back to a hardcoded `"0.1.0"` literal if built with plain `iscc packaging/installer.iss`, no `/D`). Whatever invokes `iscc` (a person, or E-18's CI step) is responsible for reading `pyproject.toml`'s version and passing it through `/D`.
- `.github/workflows/build.yml` (E-18) — `windows-latest` runner: checkout → `setup-python` (3.11) → `pip install -e .[dev]` → `ruff check .` → `pytest` → extract `version` from `pyproject.toml` via a PowerShell `Select-String` regex (verified against the real file: correctly reads `0.1.0`) → `pyinstaller packaging/scan2connect.spec` → Inno Setup CLI (`C:\Program Files (x86)\Inno Setup 6\ISCC.exe`, preinstalled on `windows-latest` runners) with `/DAppVersion=<extracted version>` → `Compress-Archive` the onedir build into a portable zip → upload both the installer and the zip as build artifacts (`actions/upload-artifact@v4`, separate artifact names). On a `v*` tag push, also attaches both files to a GitHub Release via `softprops/action-gh-release@v2`. Runs on push to `main`, on `v*` tags, and on PRs into `main`. Not run on a real GitHub Actions runner this session (would require pushing); the version-extraction regex and the portable-zip `Compress-Archive` command were both verified locally against a real onedir build from E-16, and the YAML was validated to parse correctly.

## Platform notes

- WiFi features are Windows-only. Profile creation/connect via the native WLAN API does not need elevation: `netsh wlan add profile`/`delete profile` (E-08) worked fine as a standard user, and E-09's connector code follows the same calls. Actually driving `WifiConnector` against a live adapter (`WlanConnect` succeeding end-to-end, not just schema-valid `WlanSetProfile`) is still **user-verified, not Claude-verified** — E-09 was implemented + unit-tested with `wlanapi` mocked per the user's choice, not live-connected during the session.
- `netsh wlan export profile` (reading a saved profile's XML back out) **does** require elevation on this account — hit this while trying to get a reference profile for E-08; worked around it by round-tripping generated XML through `netsh wlan add profile` instead, which validates against the same schema.
- Win11 gates WLAN *scanning* behind Location permission; connecting via a saved profile does not need it.
- Camera access can be blocked under Settings › Privacy & security › Camera.
